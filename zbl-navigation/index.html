01 / WHY

传统导航的极限，不是“走不到”

而是每换一种任务、环境或机器人，都要重新定义接口与能力边界。

01

任务泛化

传统栈擅长已知坐标上的确定性规划，却难以统一理解“去最近的椅子”“穿过走廊后左转”等不同目标形式。

02

语义探索

目标不在视野内时，导航不再只是路径搜索，而需要结合历史观察推断“应该去哪里找”。

03

跨本体迁移

直接预测离散动作或控制量会绑定机器人运动学；视觉空间中的 Pixel Goal 更接近本体无关的中间语言。

04

低传感器依赖

只使用相机完成语义理解与导航决策，减少地图、激光与精密标定带来的部署成本。

02 / SYSTEM

为什么是“大小脑”结构？

语义推理需要看得远、想得慢；运动执行需要反应快、轨迹稳。解耦规划与执行，才同时保留两者。

SYSTEM–2 · SLOW

运动小脑

条件化生成多模态连续轨迹，处理局部避障与本体动力学。

03 / DESIGN

三个设计，让 VLM 真正“会导航”

不是让模型凭空学习坐标系，而是把空间、优先级和历史明确写进任务。

A
UNIFIED OUTPUT SPACE

所有任务，统一输出 Pixel Goal

VLM 在海量图像上预训练，对像素方位的理解天然强于机器人坐标与控制量。显式指定 640×480 坐标系，减少空间表示的学习负担。

[PointNav] ... Return exactly one pixel goal (u, v).
Prefer FORWARD ... farthest navigable pixel.
(0,240) TURN LEFT · (639,240) TURN RIGHT · (320,479) STOP
B
STRONG ACTION PRIOR

先前进，再转向；先可见点，再猜测

Prompt 明确动作优先级：局部目标可见时，选择沿目标方向最远的可行走像素；目标在视野外才输出转向哨兵点。这一约束直接抑制原地打转与左右摆动。

VISIBLE → FORWARD›OUT OF VIEW → TURN›< 1 m → STOP
C
DUAL CAMERA CONTEXT

头部看语义，底盘决定落脚点

输入由指令、8 帧历史观察、当前头部图与底盘图组成。头部相机覆盖高处物体；底盘相机拥有更大的近场视野，能看到障碍与可行走区域，因此用其坐标输出 (u, v)。

<instruction><history × 8>head-view <image>chassis-view <image> → (u,v)

只有 Pixel Goal？

只取文本 hidden state？

Pixel + Latent Goal

06 / ITERATE

失败不是例外，而是设计输入

从打转、碰撞到物体漏检，每类错误都对应一项可验证的系统改动。

SPINNING

原地打转 / 左右摆动

  • Evaluator：目标在视野内时强制输出轨迹
  • Prompt 强调 prefer forward
  • 转向数据控制为正常行走的 1/3
